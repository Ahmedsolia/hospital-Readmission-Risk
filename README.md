## 1. Problem Framing

**Who has the problem:** Hospitals (discharge planners, inpatient care teams, case managers) treating diabetic patients.

**Decision supported:** At discharge time, who gets scarce follow-up resources (48h phone call, 7-day clinic slot, home-health referral, pharmacist med review)?

**Current pain:** 30-day readmissions are costly, penalized, and signal poor follow-up. Teams today triage largely by gut feel / age alone.

**ML task:** Binary classification at discharge time:
- `1 = High risk` → readmitted in `<30` days
- `0 = Low risk` → `NO` or `>30` days

**Why binary `<30 vs. rest`:** Matches the idea card ("Readmitted within 30 days Yes/No") and the hospital's 30-day quality metric. We will also report the original 3-class distribution for transparency.

**Metric that matters (business-first):**
1. **Primary: Recall @ 30-day class** — missing a high-risk patient (false negative) = missed follow-up + readmission. We optimize recall while keeping precision usable.
2. **Secondary: ROC-AUC + PR-AUC** — ranking quality under imbalance (~11% `<30` in literature — to confirm in our EDA).
3. **Operational: Precision / false-alarm rate + confusion matrix** — too many false positives = alert fatigue.
4. We will tune the decision threshold on validation data by cost (missed readmission vs. unnecessary call), not default 0.5.

## 2. Data Understanding (what we have locally)

**Source:** UCI Diabetes 130-US Hospitals 1999–2008 — https://archive.ics.uci.edu/dataset/296
**Local files (already in `D:\NextGen\`):**
- `diabetic_data.csv` — ~19 MB, 50 columns, ~101,766 encounters expected (to confirm with `shape`)
- `IDS_mapping.csv` — human-readable labels for `admission_type_id`, `discharge_disposition_id`, `admission_source_id`
- `diabetes+130-us+hospitals+for+years+1999-2008.zip` — archive of the two files above

**Column dictionary (from header inspection):**
- Identifiers: `encounter_id`, `patient_nbr` (note: same patient can have multiple encounters — risk of leakage if split naively)
- Demographics: `race`, `gender`, `age` (binned `[0-10)` … `[90-100)`), `weight` (mostly `?`)
- Admission: `admission_type_id`, `discharge_disposition_id`, `admission_source_id`, `time_in_hospital`, `payer_code`, `medical_specialty`
- Utilization: `num_lab_procedures`, `num_procedures`, `num_medications`, `number_outpatient`, `number_emergency`, `number_inpatient`, `number_diagnoses`
- Diagnoses: `diag_1`, `diag_2`, `diag_3` (ICD-9 codes, with `?` missing)
- Labs: `max_glu_serum` (`None/Norm/High`), `A1Cresult` (`None/Norm/High`)
- Meds (24 cols, values `No/Steady/Up/Down`): `metformin`, `repaglinide`, `nateglinide`, `chlorpropamide`, `glimepiride`, `acetohexamide`, `glipizide`, `glyburide`, `tolbutamide`, `pioglitazone`, `rosiglitazone`, `acarbose`, `miglitol`, `troglitazone`, `tolazamide`, `examide`, `citoglipton`, `insulin`, + 4 combos
- Process: `change` (med change during stay), `diabetesMed` (any diabetes med)
- Target: `readmitted` (`NO` / `>30` / `<30`)

**Known messiness (to handle in preprocessing):**
- `?` used as missing in `race`, `weight`, `payer_code`, `medical_specialty`, `diag_*`
- High-cardinality / sparse: `medical_specialty` (~70+ values, much missing), `diag_*` (hundreds of ICD-9 codes), `payer_code`
- `weight` extremely sparse — candidate to drop (decision after EDA missing-rate table)
- Discharge dispositions like `Expired` / `Hospice` — patients who cannot be readmitted; must exclude or special-case (leakage/bias trap — decide explicitly and document)
- Multiple encounters per `patient_nbr` — must split by patient, not by row

## 3. Target Definition & Leakage Rules

**Target construction (in code, reproducible):**
```python
y = (df["readmitted"] == "<30").astype(int)  # 1 = readmitted within 30 days
```

**Discharge-time rule:** Only features known **at or before discharge** may be used. Anything recorded after discharge is forbidden.

**Explicit leakage / exclusion audit:**
- Drop `encounter_id`, `patient_nbr` as features (keep for grouping/splitting only)
- Audit `discharge_disposition_id`: dispositions 11, 13, 14, 19, 20, 21 (Expired/Hospice) → exclude from train/eval cohort, document count and rationale; app will refuse to score these with a clear message
- No scaling/encoding/imputation fitted on full data — all inside `Pipeline`, fit on train only
- Split **by `patient_nbr` (GroupStratified)** so no patient appears in both train and test

### Phase 3 — Preprocessing inside `Pipeline` (15 pts, no leakage)
Planned `ColumnTransformer` design:
- **Numeric** (`time_in_hospital`, `num_lab_procedures`, `num_procedures`, `num_medications`, `number_outpatient/emergency/inpatient`, `number_diagnoses`): median impute → clip outliers (IQR on train) → `StandardScaler`
- **Low-card categorical** (`race`, `gender`, `age`, `max_glu_serum`, `A1Cresult`, `change`, `diabetesMed`, binned admission/source groups): most-frequent impute → `OneHotEncoder(handle_unknown="ignore")`
- **High-card categorical** (`medical_specialty` grouped to Top-N + `Other/Missing`, `payer_code` grouped, ICD-9 groups): grouping + `OneHotEncoder` (or target-free frequency grouping — no target encoding to keep it leakage-safe and simple)
- **Meds** (24 cols): collapse `Up/Down` → `Changed(1)` vs `Steady/No(0)` per drug + `num_med_changes` count feature; `insulin` kept as 4-level one-hot (hypothesized signal)
- **Feature engineering (discharge-safe):**
  - `total_prior_visits = outpatient + emergency + inpatient`
  - `polypharmacy = num_medications > threshold` (threshold from train EDA)
  - `long_stay`, `high_utilization` flags
  - ICD-9 `diag_1/2/3` → clinical groups (Circulatory 390–459, Diabetes 250, Respiratory 460–519, Digestive 520–579, Injury 800–999, Musculoskeletal 710–739, Genitourinary 580–629, Neoplasms 140–239, Other) + `diag_changed` flag
  - `admission_type_id` / `source` / `discharge` → small mapped groups via `IDS_mapping.csv` (Emergency vs Elective; Home vs Transfer etc.)
- **Drops:** `weight` (if >90% missing — confirm), `encounter_id`, `patient_nbr` (features), plus near-zero-variance cols (`examide`, `citoglipton` — confirm)
- All steps wrapped in a single `sklearn Pipeline` saved with `joblib`

## 8. Risks & Mitigations
- **Imbalance (~9:1):** balanced weights + recall-first tuning + PR-AUC; avoid accuracy storytelling
- **Patient leakage:** group split by `patient_nbr`; verify no overlap programmatically
- **Messy codes (`?`, ICD-9, 70+ specialties):** explicit grouping tables, `Other` buckets, `handle_unknown="ignore"`
- **Expired/Hospice bias:** exclude + document; app guardrail
- **Old data (1999–2008):** state as limitation; recommend recalibration on recent data before real use
- **Compute:** sample only if needed for tuning search, final fit on full train; keep grids small
